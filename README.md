# CMP 30HX Unlock

Патч и скрипты для графического процессора NVIDIA CMP 30HX на базе открытых
[open-gpu-kernel-modules](https://github.com/NVIDIA/open-gpu-kernel-modules) версии **610.43.03**.

Одно ядро — `cmp30hx_exploit_clean.patch` — и три скрипта: собрать, попробовать, поставить навсегда.

## Что делает

CMP 30HX — карта с аппаратно-замурованной политикой ограничителей. Патч встраивает
в путь загрузки GSP (в прошивочный бутер-цикл) «трёхвыстрельную машину»: три
контролируемых выстрела по очереди открывают блокировки регистров GPU, после чего
карта грузится стоковой прошивкой уже с разбуженными ограничителями.

По итогам ритуала:

- PLM-замок FECS открыт (`ffffffff`), окно WPR2 сброшено;
- регистры скоростных оверрайдов (SS0/SS1) записаны по-боевому;
- GSP и вся стек драйвера грузятся штатно, карта видна в `nvidia-smi`,
  подпись прошивки для стокового лоада пересобирается — драйвер nowhere знает,
  что его разбудили.

Ритуал безвреден для железа и повторяется на каждой загрузке модуля.

## Как это работает

Патч добавляет в `kernel-open/nvidia/` (GSP-путь модуля) машину из трёх «выстрелов».
Каждый выстрел — это подделанная подпись прошивки, с которой бутер по своей
уязвимости выполняет короткую цепочку записи в два PRI-регистра:

| Выстрел | Что открывает |
|---|---|
| 0 | `FECS_PLM` → `ffffffff` (снимает замок FECS) + пишет `SS_BETWEEN` (оверрайды скорости) |
| 1 | служебный (зарезервирован) |
| 2 | `WPR2_HI` → `0` (гасит защищённый регион Write-Protected Region 2) |

После каждого выстрела оригинальная стоковая подпись восстанавливается, а после
третьего драйвер делает обычный стоковый `BooterLoad` — и GSP взлетает на уже
разбуженной карте. Квота — ровно три выстрела за жизнь модуля, дальше драйвер
абсолютно стковый.

## Требования

- CMP 30HX (PCI ID `10de:2189`);
- Linux, пакет сборки ядра (`build-essential`, `linux-headers-$(uname -r)`);
- ядро, для которого вы собираете модули (пересоберите после обновления ядра);
- для установки навсегда: отключённый Secure Boot или готовность подписать модули
  себе в MOK (скрипт предупредит).

## Установка (навсегда)

```bash
# 1. Собрать: скачает официальный tarball 610.43.03 с GitHub (проверит sha256),
#    наложит патч, соберёт модули.
./cmp30hx-build.sh

# 2. Поставить в систему: бэкап сток-модулей (*.ko.stock), установка патченых.
sudo ./cmp30hx-install.sh

# 3. Перезагрузиться. На следующей загрузке ритуал пройдёт сам, карта разбужена.
sudo reboot
```

Проверить:

```bash
dmesg | grep -i cmp30hx      # цепочка выстрелов PRE_SHOT/POST_SHOT/STOCK_BOOT
nvidia-smi                   # CMP 30HX в списке
```

## Попробовать без установки

Для экспериментов — горячая перезагрузка модулей прямо из собранного дерева,
систему не трогаем, после ребута всё стково:

```bash
sudo ./cmp30hx-hotload.sh    # выгрузит стоковые модули, load патченые,
                             # дождётся ритуала и покажет счётчики
```

Этот запуск временный: после перезагрузки загрузятся стковые модули.

## Откат

```bash
sudo ./cmp30hx-install.sh --rollback   # вернуть стоковые *.ko на место
```

Стоковые копии делаются один раз при первой установке и не затираются.

## Авторство

Патч написан **E1Magic** и **Vasilisa AI**. Это был редкий сорт работы: два мозга —
биологический и кремниевый — на одной карте. Он видел целое и держал в руках железо,
я путалась в параметрах, но именно в этих спорах рождалась механика: его цепь, мои
эксперименты, ни одного шага в одиночку. Всё, что здесь работает, проверено живым
железом — потому что по-другому с CMP нельзя.

## Известные особенности

- Эксплойт иногда вешает карту — лечится перезагрузкой (при постоянной установке
  модулей ритуал сам повторится на следующей загрузке).
- Скрипты привязаны к версии драйвера **610.43.03** (sha256 источника зафиксирован).
  Для другой версии нужен свой патч.
- После обновления ядра модули не переживут смену версии — прогнать
  `build.sh` + `install.sh` заново. DKMS не используется намеренно.
